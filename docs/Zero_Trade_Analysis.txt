🔴 Root Cause #1: Swing Filter is a HARD GATE (Not a Soft Scorer)
The single biggest reason for zero trades.

The swing filter in stock_reversal_scanner.py works as a hard gate:

python

# Current behavior: HARD REJECT
if not swing_result.get("matched", False):
    log.info(f"Skipping {symbol} - failed parabolic swing cascade filter")
    continue  # ← Symbol is COMPLETELY SKIPPED
This means: Even if a stock has a textbook-perfect Bullish Engulfing at a 52-week low with pristine A-B-C-D breakout and 5:1 R:R, it is invisible to the scanner if it doesn't ALSO have 3 parabolic arches with R² ≥ 0.55.

The swing filter kills 31.4% of your universe before BCD detection even runs.

 R² Threshold
Your config has swing_min_r2 defaulting to 0.55 (set in code, not overridden in config). Real Indian equity price action is noisy — gaps, wicks, news-driven spikes break the clean polynomial curve. Most valid exhaustion patterns have R² of 0.30–0.45.

CAUTION

The swing filter was designed as a quality SCORING layer (T1 Gold / T2 Core / T3 Momentum) but is being used as a binary kill-switch. This defeats its entire purpose.

The gatekeeper requires Anchor A date >= terminal swing base date. But think about what this means:

The stock makes a multi-leg downtrend (detected by swing filter)
The terminal swing base forms at the BOTTOM (e.g., Aug 14)
The Anchor (reversal candlestick) forms BEFORE the base completes
This is a logical contradiction. The anchor IS the reversal signal AT the terminal base. They should be contemporaneous, not sequential. The anchor often forms 1-2 candles before the base is "confirmed" by the swing detector (which needs forward-looking bars).

Result: 9 stocks with valid setups (ETERNAL, ONGC, TITAN, APOLLOHOSP, NESTLEIND, ULTRACEMCO, BPCL, AXISBANK, TATACONSUM) are being rejected because their anchor candle is a few bars older than when the swing detector declares the base "terminal."

🟡 Root Cause #6: Left-Side Rule Contradicts Downtrend Premise
